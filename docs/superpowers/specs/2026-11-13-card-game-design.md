# 실시간 색깔 카드게임 (가제: 컬러팡) — 설계 문서

작성일: 2026-11-13
상태: 선생님 최종 승인 대기 (질문 답변 반영 완료)

---

## 1. 무엇을, 왜 만드는가

- 색깔·숫자를 맞춰 손패를 먼저 다 내려놓는 **쉐딩(shedding) 카드게임**을 태블릿용 웹앱으로 만든다.
- 규칙 계열은 널리 알려진 방식(색/숫자 맞추기, 건너뛰기·방향 바꾸기·+2·와일드·와일드+4)을 따르되,
  **'우노' 이름·로고·카드 디자인은 쓰지 않는다.** 이름과 카드 그림은 모두 새로 만든다.
- **쓰는 상황**: 초등학교 쉬는 시간(약 10분), 학생 22명 이상이 여러 방에 나뉘어 동시에 플레이.
- **최종 목표**: 좋은 퀄리티로 완성해 **인디스쿨에 배포** → 다른 선생님이 받아서 설치 없이 바로 사용.
- **절대 조건**: 방 코드로 입장하고, 모든 태블릿이 **실시간 연동**되어야 한다.

### 목표
- 방 만들기 → 6자리 방 코드 → 친구 입장 → 방장 시작 → 모든 화면 동시 전환.
- 한 방 **2~4명**. 여러 방이 동시에 돌아가도 서로 간섭 없음.
- 쉬는 시간 안에 한 판이 끝나는 템포.
- 설치 0개: HTML 파일 1개(또는 GitHub Pages 링크)로 바로 실행.

### 하지 않을 것 (Non-goals)
- 로그인/계정, 점수 누적 랭킹, 채팅, 컴퓨터(AI) 상대.
- 휴대폰 세로 화면 최적화 (태블릿 가로 기준. 휴대폰은 '동작은 함' 수준).
- 해킹 방지 수준의 보안 (초등 쉬는 시간 게임 기준으로 판단).

### 실패로 간주할 것 (Anti-goals)
- 누군가 태블릿을 끄거나 나가면 그 방 게임이 멈춤.
- 화면마다 바닥 카드·차례가 서로 다르게 보임(동기화 어긋남).
- 첫 접속에 30초 이상 기다려야 함 (쉬는 시간이 날아감).
- 원작 게임 이름·카드 디자인을 그대로 베낀 것처럼 보임.

## 2. 방법 비교 (Approaches)

| 방법 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. 13클루 방식 그대로 | 방장 태블릿이 심판, 공용 중계소(MQTT)는 전달만 | 설치 0개 | 방장이 나가면 게임 멈춤 |
| B. Render 서버가 심판 | 서버가 카드 관리 | 안정·공정 | 선생님마다 서버 구축 필요, 무료 서버 잠듦(첫 접속 30초~1분) |
| **C. A + 심판 이어받기 (선택)** | A 기반 + 판 전체 상태를 계속 공유 → 방장 이탈 시 다음 사람이 자동 승계. 통로는 공용 중계소 기본, 개인 서버 선택 | 설치 0개 + 끊김에 강함 + 방화벽 대비책 | 기술적으로 아는 사람은 남의 패를 엿볼 수 있음(초등 대상 허용) |

**선생님 선택: C.** 개인 서버(Render)는 **13클루와 동일하게 선택 사항**.

## 3. 실시간 구조 (선생님이 정한 부분 + 세부 설계)

### 3-1. 통신 통로 — 13클루 `realtime.ts` 구조 재사용
우선순위:
1. **개인 서버(선택)**: 설정(⚙️)에 `wss://...` 주소를 저장했거나, 개인 서버 주소로 접속한 경우 → 해당 WebSocket 사용.
2. **공용 클라우드(기본)**: `wss://broker.emqx.io:8084/mqtt` → 실패 시 `wss://broker.hivemq.com:8884/mqtt` 자동 전환.
3. **BroadcastChannel**: 같은 PC 여러 탭 테스트용.

- MQTT 토픽: `colorpang_v1/room_<방코드>` (13클루와 겹치지 않게 별도 이름).
- localStorage 키: `colorpang_relay_server` (13클루와 별도).
- 개인 서버: 13클루 `server.cjs`(방별 브로드캐스트 중계)를 이름만 바꿔 재사용. 같은 서버가 `index.html`도 제공.
  배포 안내문에 Render 구축 방법(13클루 안내문과 같은 형식) 포함.

### 3-2. 심판(호스트) 방식
- **심판 1명**(처음엔 방장)이 진짜 판 상태를 가진다: 카드 더미, 버린 더미, 모든 손패, 차례, 방향, 쌓인 +2/+4 수, 선택된 색, "한 장!" 상태.
- 다른 플레이어는 **행동 요청**만 보낸다: `카드 내기(카드ID, 와일드 색)`, `카드 뽑기`, `한 장! 외치기`, `잡았다!`.
- 심판은 요청을 규칙대로 검사 → 적용 → **판 전체 스냅샷(버전 번호 포함)**을 방 전체에 발송.
- 각 태블릿은 스냅샷에서 **자기 손패만 앞면**, 남의 손패는 장수만 표시.
- 버전 번호가 이전보다 작은 스냅샷은 무시 (순서 뒤바뀜 방지).
- 공용 중계소 메시지는 보장이 약하므로, 심판은 **2초마다 생존 신호 + 최신 버전 번호**를 보내고,
  버전이 뒤처진 태블릿은 스냅샷 재요청.

### 3-3. 심판 이어받기
- 모든 플레이어가 2초마다 생존 신호 전송.
- 심판의 신호가 **6초간** 끊기면 → 살아있는 사람 중 **자리 번호가 가장 빠른 사람**이 마지막 스냅샷으로 심판을 이어받는다.
  (모두 같은 규칙으로 계산하므로 별도 투표 없음.)
- 원래 심판이 돌아오면 일반 플레이어로 합류.

### 3-4. 끊김·재입장
- 각 기기는 `clientId`와 방 코드, 자리 번호를 localStorage에 기억.
- 새로고침/잠깐 꺼짐 → 같은 방 코드로 다시 들어오면 **같은 자리, 같은 손패**로 복귀.
- 차례인 사람이 끊겨 있으면 화면에 "○○ 연결 끊김" 표시, 30초 차례 제한(4-3-1)에 따라 자동 진행.

### 3-5. 방 코드
- 13클루와 같은 6자리 숫자 코드, 키패드 입력. 인원 정보 자릿수는 쓰지 않고 6자리 랜덤.
- 대기실: 자리 1~4 선택 + 이름 입력, 참여 현황 실시간 표시, 방장 [게임 시작] → 전원 동시 전환. 2명 이상이면 시작 가능.

## 4. 게임 규칙

### 4-1. 카드 구성 (총 108장, 장르 표준 구성)
- 4색 × (0 한 장, 1~9 두 장씩) = 76장
- 4색 × (건너뛰기·방향 바꾸기·+2 각 2장) = 24장
- 와일드 4장, 와일드+4 4장

### 4-2. 진행
- 각자 7장, 더미에서 한 장 뒤집어 시작(와일드+4가 나오면 다시 섞음, 특수카드면 그 효과로 시작).
- 바닥 카드와 **색 또는 숫자/기호가 같으면** 낼 수 있음. 와일드는 언제나 가능.
- 낼 카드가 없으면(또는 내기 싫으면) 1장 뽑기 → 뽑은 카드가 낼 수 있으면 바로 낼 수 있음, 아니면 차례 끝.
- 2명일 때 방향 바꾸기 = 건너뛰기.
- 손패를 먼저 다 내면 승리 → 결과 화면 → 방장 [한 판 더] (같은 멤버로 재시작). 점수 누적 없음.

### 4-3. +2 / +4 쌓기 — **허용 (선생님 결정)**
- +2를 받은 사람은 +2를 내서 다음 사람에게 넘길 수 있음 (누적).
- 쌓을 카드가 없으면 누적된 장수를 뽑고 차례 쉼.
- 세부 (**선생님 확정**): +2와 +4는 서로 자유롭게 쌓을 수 있음 (+2 위에 +2·+4, +4 위에 +4·+2 모두 가능). +4 도전(블러핑 확인) 규칙은 없음.
- 빌더 제안: 쌓는 중에는 색과 상관없이 +2/+4를 낼 수 있음. +4 위에 +2를 내면 현재 색은 그 +2의 색으로 바뀜.

### 4-3-1. 차례 시간 제한 — **30초 (선생님 결정)**
- 매 차례 30초. 화면에 남은 시간 막대 표시, 마지막 5초는 깜빡임.
- 시간 초과 시 심판이 자동으로 처리: 쌓인 +2/+4가 있으면 그만큼 뽑고, 없으면 1장 뽑고 차례 넘김.
- 와일드 색 고르기 중 시간 초과 → 그 사람 손패에 가장 많은 색으로 자동 선택.
- 타이머 기준은 심판 기기 시각(차례 시작 시각을 스냅샷에 포함). 심판 이어받기 시 남은 시간 이어감.
- 연결이 끊긴 사람의 차례도 같은 30초 규칙으로 자동 진행 (3-4의 비상 버튼은 이것으로 대체).

### 4-4. "한 장!" 외치기 — **버튼 방식 (선생님 결정)**
- 카드를 내서 1장이 남으면 그 사람 화면에 큰 **[한 장!]** 버튼.
- 누르기 전에는 다른 사람들 화면에 **[잡았다!]** 버튼 표시.
- 다음 사람이 카드를 내거나 뽑기 전에 누군가 [잡았다!]를 먼저 누르면 → 그 사람이 **벌칙 2장**.
- 본인이 먼저 [한 장!]을 누르면 안전, 모든 화면에 "○○: 한 장!" 표시.
- 동시에 누르면 심판에게 먼저 도착한 요청 기준.

## 5. 화면과 디자인

### 5-1. 화면 흐름
`시작(방 만들기 / 방 코드로 입장 / 규칙 보기 / ⚙️ 서버 설정)` → `대기실` → `게임` → `결과` → (한 판 더)

### 5-2. 게임 화면 (태블릿 가로)
```
┌──────────────────────────────────────────────┐
│ [방 482910] [🟢 공용 클라우드]        [규칙] [나가기] │
│      [민수 🂠×5]     [영희 🂠×3 한 장!]    [지훈 🂠×7]   │
│                                              │
│          [더미 🂠]   [바닥 카드]  ↻ 방향         │
│                     현재 색: 🔵   +4 쌓임       │
│              ▶ 지금 차례: 나                    │
│                                              │
│   (내 손패 — 낼 수 있는 카드는 위로 살짝 떠 있음)      │
│   🂡 🂡 🂡 🂡 🂡 🂡 🂡 🂡           [한 장!]/[잡았다!] │
└──────────────────────────────────────────────┘
```
- 내 차례일 때 화면 테두리 강조 + 낼 수 있는 카드만 활성화.
- 카드를 탭하면 바닥으로 날아가는 애니메이션, 다른 사람 화면에서도 해당 자리에서 날아옴.
- 손패가 많으면 겹쳐 펼치기 + 좌우 스크롤.
- 와일드를 내면 색 고르기 창.

### 5-3. 카드 디자인 (빌더가 새로 디자인 — 선생님이 맡김)
- 원작과 다른 독자 디자인: 둥근 사각형, 원작의 기울어진 타원 문양 사용 금지.
- 4색마다 **모양 기호를 함께** 넣어 색약 학생도 구분: 예) 빨강 ● / 노랑 ★ / 초록 ▲ / 파랑 ◆.
- 특수카드는 자체 이름·아이콘: 건너뛰기, 방향 바꾸기, +2, 무지개(와일드), 무지개+4.
- 이미지 파일 없이 SVG/CSS로 그려 HTML 1개 용량을 작게 유지.
- 구현 초기에 카드 시안을 선생님께 보여드리고 확정.

### 5-4. 게임 이름
- 가제 **"컬러팡"** — 빌더 제안, 선생님이 바꿀 수 있음.

## 6. 기술 구성 (빌더 결정)

- 13클루와 같은 스택: **Vite + React + TypeScript + mqtt.js**, `vite-plugin-singlefile`로 **index.html 1개** 빌드.
- 개인 서버: Node `ws` 기반 `server.cjs` (13클루 것 재사용).
- 게임 규칙 로직(카드 검사, 쌓기, 한 장 판정, 이어받기 판정)은 화면과 분리한 순수 함수로 만들고 **자동 테스트** 작성.
- 같은 PC 여러 탭(BroadcastChannel) + 실제 공용 클라우드로 4인 동시 플레이 확인.
- 배포: GitHub Pages(13클루와 동일) + 인디스쿨용 **배포 안내 가이드.md** (공용 사용법 / 개인 Render 서버 구축법).
- 프로젝트 폴더: `E:\00 초등학교\11 바이브코딩\우노` (현재 git 저장소 아님 — 구현 시작 시 git 초기화 제안).
